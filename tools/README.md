# EO development content importer

`import_eo.py` converts one map and its referenced graphics to the Godot content contract. It does not launch legacy executables, extract executables, start a server, or fetch source archives automatically. ZIP members are size limited and read in memory; output filenames are generated by the importer.

Requires Python 3.10+ and Pillow (`python3 -m pip install Pillow`). Run from the repository root after obtaining source archives you have permission to use:

```sh
python3 tools/import_eo.py \
  --sample-data /path/to/sample-data.zip \
  --client-zip /path/to/EOzipped028.zip
python3 tools/test_import_eo.py
```

To import elsewhere use `--output /absolute/path/to/client/content`. The `--map` argument selects a numbered map, default 5 (Aeven). For tests, `EO_DATA_DIR` can override the source archive directory. Real-data integration checks skip when the archives are unavailable. Reference archives and generated assets are not included in the public repository. Keep local downloads in the ignored `reference/` directory.

The default export is the complete 87×87 Aeven map, not a synthetic approximation. Spawn `(40,40)` has a clear seven-by-seven neighborhood. The importer preserves 26 map NPC spawn records, chest and warp records, encoded map text, all nine layers, and tile specifications. It exports only the map's referenced graphic IDs, selected item samples, and character frames. NPC records and warps are reference data; their presence does not imply runtime AI, transitions, quests, or network support.

`manifest.json` records source archive hashes, exact source URLs, graphics paths/dimensions, layer mapping, character frames, sound effects, and limitations. Character sprites are composed from classic male skin, hair, armor, and boots using the source renderer's frame selection and offsets. The prototype precomposes eight equipment combinations and switches among them at runtime; arbitrary equipment compositing is future work. `manifest.characters.hero_variants` keys are `a0_b0_w0` through `a1_b1_w1`, where the bits select armor, boots, and weapon. Every combination includes the complete four-direction idle, walking, and attack animation sets. `hero` aliases `a1_b1_w0`; `hero_equipped` aliases `a1_b1_w1`. `source_resources` records source EGF members and graphic IDs for each variation. The training creature uses green slime graphic 3, with its actual individual standing, walking, and attack resources. Frame dictionaries are keyed `south`, `east`, `north`, `west`. Each frame has `path`, `region:[x,y,w,h]`, and `offset:[dx,dy]` relative to a bottom-center entity anchor. Hero frames include eight transparent pixels below the feet, represented by offset `[0,8]`.

`manifest.sounds` includes melee attack, inventory pickup, and punch effects from `sfx015.wav`, `sfx020.wav`, and `sfx010.wav`. Some original WAV files report incorrect RIFF lengths or include bytes after their declared PCM data. The importer writes canonical WAV files from the declared PCM frames with exact lengths; the manifest preserves original member names/hashes and repair metadata. No MIDI conversion is included.

`manifest.starter_equipment` is parsed from the original client’s `pub/dat001.eif`, rather than guessing which icons match the character: armor is Soldier Plate (item143, male armor graphic1, icon312), boots are Blue Boots (item80, boot graphic1, icon176), and weapon is Dagger (item21, weapon graphic4, icon76). These are local prototype appearance definitions; the separately supplied server PUB data may use different identifiers. Every equipment entry includes its source member and ground/inventory graphic keys.

`manifest.paperdoll` includes the original male paperdoll background and silhouette panel, extracted from GFX2 graphic49, plus the fifteen original equipment slot rectangles. Crop rectangles and the source member are recorded. The original panel is 380×290; the silhouette crop is 200×266. Both retain opaque UI colors rather than using sprite color-key transparency.

Building alignment follows the base renderer’s per-layer offsets in addition to each specialized renderer. In particular right walls have a +32px horizontal offset relative to down walls; omitting that base offset splits house corners. With this client’s tile-center basis, down walls draw at `(-32,15-height)`, right walls at `(0,15-height)`, objects/overlays at `(-width/2-2,14-height)`, roofs at `(-32,-80)`, top tiles at `(-32,-48)`, and shadows at `(-56,-28)` with alpha0.2. `manifest.reference_layer_offsets` documents the exact mapping. Aeven’s visible building tops are largely object sprites; this map contains no entries in the dedicated roof layer.

The current twelve tests cover base-253 number boundaries, an independently captured encoded Aeven-name fixture, truncated input, archive traversal/size rejection, all 289 real map files, known Aeven counts, walkable spawn, PE resource offsets, black color-key transparency, every exported map graphic reference, character frame dimensions, repair of the malformed WAV header, actual classic item definitions, and eight pixel-distinct equipment combinations.

Reference implementation: [EndlessClient](https://github.com/ethanmoffat/EndlessClient), especially `EOLib.IO/Services/Serializers/MapFileSerializer.cs`, `MapPropertiesSerializer.cs`, `MapStringEncoderService.cs`, `Rendering/Sprites/CharacterSpriteCalculator.cs`, `NPCSpriteSheet.cs`, character property renderers, map entity renderers, and `Audio/SoundEffectID.cs`. Current EndlessClient source is MIT licensed. The original game artwork, maps, and audio have separate unresolved publication rights. Asset extraction and local development use do not establish redistribution permission.


## Runtime catalog for online play

After importing base content, run the catalog exporter against the exact staged server data. It reads PUB files and maps without modifying the running server or database:

```sh
python3 tools/export_catalog.py \
  --runtime /path/to/staged/runtime \
  --graphics-zip reference/gfx.zip
python3 -m unittest discover -s tools -v
```

`catalog.json` contains 490 item definitions, 302 NPC definitions, and metadata for 282 maps from the staged etheos runtime. `items` and `npcs` are dictionaries keyed by decimal definition ID strings. Map metadata includes dimensions, names, original spawn records, and source hashes. All 282 maps have compact geometry JSON under `content/maps/`; map records include each resource path. All item inventory and ground icons are exported. 160 world NPC graphic sets (including restored Princess and Ancient Wraith) are added under `manifest.characters.npcs`, keyed by graphic ID strings; definition ID resolves through `catalog.npcs[id].graphic`. The eight starter hero variants remain available. NPC frames include the exact direction-dependent position and second-attack offsets from `NPCMetadataProvider.cs` and `NPCRenderer.UpdateDrawAreas`, including the original `23-yOffset` baseline. All exported NPC sets have explicit `render_metadata`; frame offsets are already applied by the generic bottom-center renderer and must not be added again by the caller. Name labels use `-32-name_label_offset` relative to the tile center. `catalog.money_graphics` provides the five original coin piles at amount thresholds0,2,100,10000,100000; money item ground rendering should select the greatest threshold not exceeding the stack amount. Every source PUB hash and graphics archive provenance is recorded; original game content remains ignored local reference material.

Snapshot character appearance graphics are in the actual etheos `B000A0HSW` order: boots at0, armor at4, hat at6, shield at7, weapon at8. Character selection uses five graphics in `BAHSW` order. These are doll graphic IDs, not inventory item IDs. Legacy starter variants cover armor0/1, boots0/1 and weapon0/4. Runtime equipment layers version2 now cover both genders, seven skins, every native hairstyle/color, and all visible catalog equipment. Headgear uses original Standard/FaceMask/HideHair rules; offhands change depth with facing. Ranged attacks use the original GFX008/7 skin pose, armor21/22 and weapon18/19 shooting resources and matching equipment offsets; standing, walking and melee frames retain their existing pixels. Sitting poses still need work. `catalog.appearance_bindings` records these bindings explicitly. The catalog describes definitions; ownership, positions, health, combat, and inventory changes must come from the server.

The combined importer/catalog suite currently has 29 passing tests. Catalog tests verify exact staged PUB hashes, real equipment definitions, every map5 NPC’s graphic binding, every item icon, malformed PUB rejection, every selected NPC frame offset, independently calculated guard attack/direction fixtures, and all five coin pile images/thresholds. Re-running the base importer resets the manifest; run the catalog exporter afterward to restore online bindings.

`audit_archives.py` performs CRC validation, whole-file graphics comparisons, PE bitmap count/dimension inventories, and actual legacy map/PUB parsing. Example:

```sh
python3 tools/audit_archives.py \
  --baseline /path/to/EOzipped028.zip \
  --gfx reference/gfx.zip \
  --delta reference/trunk-305-EODelta.zip \
  --runtime /path/to/staged/runtime \
  --output reference/reports/archive-audit.json
```

The supplied graphics archive’s 25 EGF files (15,580 bitmap resources) are byte-for-byte identical to the existing v28 graphics. The EODelta archive contains three small maps, plus classic-format PUB files. Its shared PUB definitions match the runtime baseline; it adds one item and two NPC definitions. It is not a replacement for the current 282-map world. The audit report and provided archives stay under ignored `reference/`; they are not public source artifacts.

The world validator records 3,945 warps; 228 maps are graph-reachable from Aeven when ignoring level/key requirements. Eight original map47 warp destinations exceed map bounds and remain recorded as invalid. Graphic171 (Ancient Wraith) intentionally has transparent idle/walking art in the original archive, while attack resources 6813–6816 are visible. The importer preserves these transparent poses and their original attack artwork, so no missing-art ball is drawn. Other blank unused poses still fall back to the same NPC standing pose and retain provenance. No replacement species artwork is invented. To repair an existing content pack without rebuilding unrelated maps or player art, run `python3 tools/export_wraith.py --graphics reference/gfx.zip`. Classic and Enhanced share this NPC data.


Version 0.10 catalog export also composes 24 original weapon appearances under
`manifest.characters.weapon_variants`: the six items 19,22,32,37,38,281 combined
with armor/boots off/on. Keys are `a{armor}_b{boots}_g{weapon_doll_graphic}`;
the eight existing starter variants remain unchanged. Extra weapons use a
192×192 transparent canvas to retain long blade art, with the same feet anchor
and original layer offsets. The native equipment doll graphic selects the
appearance; item ID and bag icon are not substituted for doll graphic ID.
The runtime continues to flag other unsupported character appearances.


Original action sound bank (v0.29.1): after running the base importer/catalog export, run:

```sh
python3 tools/export_sfx.py --client-zip work/eoserv-crawl/downloads/EOzipped028.zip --original-client work/EndlessClient
python3 -m unittest discover -s tools -p test_sfx.py
```

This preserves all81 original PCM effects and records original/source hashes in
`manifest.sfx`. `sfx_config` imports the pinned client’s75 weapon mappings,34
effect mappings and named sound aliases. Playback IDs are one-based: the original
SfxPlayer uses dictionary[id-1], whose key0 contains sfx001.wav. Melee15 therefore
means sfx015.wav; the old prototype’s three aliases were offset by one. Ordinary
health potions have no dedicated SFX in the original; confirmed spells, effect
potions, weapons, NPC attacks and acknowledged actions use their original cues.
Music export remains a separate step; its45 original tracks are retained.


Castle restoration (v0.30): after catalog export, preserve the supplied arena
configuration and export the added Princess spawn and original GFX021/115 art:

```sh
python3 tools/export_castle.py --runtime work/server-build/runtime \
  --source "reference/extracted/trunk-305-EODelta/trunk 305 EODelta/data/arenas.ini" \
  --graphics work/eoserv-crawl/downloads/EOzipped028.zip
```

This updates only six map records and Princess assets, retains native blocking
specifications and refreshes the catalog checksum. Arenas use the supplied gate
coordinates and90s rounds (46/183/184),30s (137/138). The original Princess151
is a passive combatant with13000HP; no supplied map spawns her. This restoration
adds her near the current King in map281, with the original sprites and stats.
The placement/180s respawn are restoration choices, not claimed historical coordinates.

To restore combat/protection roles from the supplied official v28 NPC data while
keeping later protected quest-giver conversations:

```bash
python3 tools/export_npc_combat.py \
  --runtime work/server-build/runtime \
  --original-client work/eoserv-crawl/downloads/EOzipped028.zip \
  --output client/content
```

This verifies the reference ENF hash, compares all 255 shared NPC definitions,
restores King 123 and Vitaman 227, validates every loaded quest kill requirement,
and refreshes the Android catalog checksum. The 47 later server NPCs have no
counterpart in this client archive and retain their supplied definitions. The
migration changes only two type fields and the PUB revision, preserving stats,
art, quests and map spawns. `server/setup.py` also applies it to fresh runtimes.
For an existing server, stop and back up the world first, run
`server/configure_npc_combat.py --runtime <runtime>`, then restart both native
world and gateway so their PUB caches agree. Rebuild Android after export.

### Fairy Soda emote graphics

After the base/catalog import, export the original GFX002 resource38 sheet:

```sh
python3 tools/export_drinks.py --archive reference/gfx.zip
```

This preserves existing artwork/music/catalog bindings and adds the original
15 emote sets × 4 frames (50×50 each), with drunk at set10. The renderer uses
240ms per frame. Source EGF hash is recorded in `manifest.drinks`. Re-run this
export after a base importer resets the manifest. The original chat corruption
rules come from pinned EndlessClient `EOLib/Domain/Chat/ChatProcessor.MakeDrunk`;
Fairy Soda's potency comes from the native EIF union at offsets32–34.

The same `export_sfx.py` command now also imports the original 36 harp and 36
guitar note WAVs into `manifest.bard_notes`, separately from the 81 ordinary
sound effects. `test_sfx.py` verifies that every note retains the original PCM
frames. These generated audio files and the supplied archive remain ignored by
Git. Bard uses the native equipped instrument graphic (49 harp, 50 guitar),
with note indices 0–35.

Quest progress/history uses the original GFX2:68 objective icons, included by
`export_catalog.py`. For an existing content pack:

```sh
python3 tools/export_quests.py --graphics /path/to/EOzipped028.zip
```

The full-screen login uses original GFX1:31 artwork. `export_catalog.py`
includes it; existing packs can run `tools/export_login.py --graphics /path/to/EOzipped028.zip`.
